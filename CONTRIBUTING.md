# Contributing

Bug reports, sprite packs, and patches are all welcome. The project is small and
deliberately dependency-light, so most changes are a single file.

## Getting set up

```bash
git clone https://github.com/HaneulOscarLee/claude-pet.git
cd claude-pet
sudo apt install python3-gi python3-gi-cairo gir1.2-gtk-3.0 python3-pil
./claude-pet doctor
```

There is nothing to build and no virtualenv. It runs from the checkout.

For day-to-day work, run the overlay in the foreground so you can see
tracebacks, rather than letting the hook autostart a detached one:

```bash
claude-pet stop
claude-pet run
```

## Running the checks

```bash
python3 tests/test_aggregate.py          # aggregation, dwells, liveness
python3 -m compileall -q claude_pet
python3 -c "import claude_pet.overlay"   # catches GI version mistakes
claude-pet demo                          # every animation row, in the real window
claude-pet doctor
```

CI runs the same things, plus a headless overlay import under `xvfb`.

## How the pieces fit

```
Claude Code hook ──> claude-pet hook ──> state.json ──> overlay (polls, 250ms)
```

| File | Role |
|---|---|
| `claude_pet/hook.py` | hook event → pet state. Runs on **every tool call** |
| `claude_pet/state.py` | the shared state file, aggregation, dwells, liveness |
| `claude_pet/overlay.py` | the GTK window: animation, bubble, walking, input |
| `claude_pet/sprites.py` | atlas parsing, v1/v2 layouts, frame slicing |
| `claude_pet/launch.py` | starting the overlay detached |
| `claude_pet/locate.py` | recording where a session runs |
| `claude_pet/jump.py` | jumping back to it |
| `claude_pet/registry.py` | the codex-pets.net client |
| `claude_pet/cli.py` | the command line |

Two constraints are worth knowing before you change anything:

**The hook path must stay fast and stdlib-only.** It runs inside every Claude
turn, currently around 33ms. Importing Pillow or GTK there, or making a network
call, would tax every tool call the user ever runs. `cli.py` imports `sprites`
and `registry` lazily for exactly this reason. If you add a module the hook
touches, keep it stdlib.

**The hook must never fail.** `hook.main()` catches everything and always exits
0. A broken pet is a cosmetic problem; a hook that raises is the user's session
broken.

## Things that are the way they are on purpose

- **XWayland, not Wayland.** `_NET_WM_STATE_ABOVE` is the only always-on-top
  mechanism mutter honours for an ordinary client, so the launcher pins
  `GDK_BACKEND=x11`. `gtk-layer-shell` is wlroots-only.
- **No Wayland fallback for click-to-jump.** `org.gnome.Shell.FocusApp`,
  `.Introspect` and `.Eval` all answer `AccessDenied`, and xdg-activation needs
  a token only the target application can produce.
- **Frame counts are measured from the alpha channel**, not read from the
  published table. Real packs sometimes draw a frame past the nominal count.
- **Dwells apply per session, not to the aggregate.** A finished session must
  stop speaking for the ones still working. See `tests/test_aggregate.py`.
- **The overlay owns its position.** Reading it back from GTK each walk step
  accumulates frame-versus-client offset error and the pet drifts off screen.
- **The overlay never writes a whole settings snapshot.** Use `config.update()`,
  or you will silently undo any `claude-pet set` made while it was running.

## Style

Match the surrounding code. In short: full words over abbreviations, type hints
on function signatures, and comments that explain *why* rather than restating
the line. If a constant encodes a decision, say what the decision was.

No formatter or linter is enforced. Lines are kept under about 100 characters.

## Pull requests

- One concern per PR.
- Say how you verified it. "Tested on GNOME 46 Wayland, pet still on top" is
  worth more than a green checkmark.
- Note the desktop you tested on. Nearly every bug in this project so far has
  been environment-specific, so X11-versus-Wayland and your compositor matter.
- New behaviour that can be wrong quietly (aggregation, liveness, sprite
  parsing) should come with a case in `tests/test_aggregate.py`.

## Sprite packs

Packs are **not** vendored here. `assets/pets/pocket` is the only bundled one,
and it is generated by `tools/make_default_pack.py` so the repository ships no
art it does not own. Please do not add someone else's pack to the repo — publish
it on [codex-pets.net](https://codex-pets.net/) instead, and it will work with
`claude-pet add <id>` immediately.

If you want to change the bundled pet, edit the generator and re-run it:

```bash
python3 tools/make_default_pack.py
claude-pet demo --pet pocket
```

## Reporting bugs

Include the output of `claude-pet doctor` and `claude-pet status`. Between them
they cover the desktop session type, the display backend, which packs are
installed, whether the hooks are wired, and which sessions the pet can see —
which is where the answer usually is.
